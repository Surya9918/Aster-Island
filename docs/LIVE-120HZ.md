# Monochrome living island and 120 Hz validation

The island now uses neutral grayscale vector materials, controls, icons and typography. Custom colors in secondary settings are converted to luminance. Real album cover images remain the player’s original content. The decorative star on the island was replaced with an original vector eye in compact/header/notification presentations. The eye follows pointer movement inside Aster’s window and blinks naturally every 6.4 seconds. It uses no camera, webcam, global cursor tracking, inference service or network. It renders on demand and sleeps between movements/blinks. Album covers still replace the compact eye while media artwork is available.

Night mode is available from Sound controls, the tray menu and Appearance. Its preference is stored locally. It smoothly lowers sheen, darkens the material, dims content, reduces gaze motion, lengthens blinks and uses lower-stiffness, more-damped springs throughout island morphing, faders and notification cards. Reduced-motion preference remains supported. This feature changes Aster’s appearance only; it does not change Windows brightness, system Night light, sound or taskbar settings.

Headphone cards use the native Core Audio endpoint-notification callback. Callbacks enqueue a dirty flag; device enumeration runs off the UI thread and coalesces events. Windows headset/headphone endpoint form factors determine classification, not guessed brand names. First enumeration is quiet. New active endpoints produce connection cards, disappearance/inactivation produces disconnect cards, and switching default output to an already-connected headphone produces an output-selected card. Existing notification physics and session inbox are reused. Battery values are not invented. No audio is recorded; device IDs/names are not logged or uploaded. COM interfaces/PROPVARIANTs are released after reads and the callback is unregistered at shutdown. Physical connection testing is pending because headphones were unavailable during validation.

## Display and frame timing

The Surface’s current Windows mode was 2304 × 1536 at 60 Hz. A 120 Hz mode at the same resolution was enumerated, tested and applied through Windows display-mode APIs at the user’s request. The final mode was verified at 120 Hz. The app follows WPF composition refresh; it does not use an artificial 8 ms polling timer or repeatedly change the display. On another display choose the desired supported refresh rate in Windows Advanced display settings. Settled animations sleep to avoid wasting battery.

Legacy rendering now reuses spring/view arrays, page transforms, shadow brushes, the surface clip, material pen and artwork brush. Formatted-text cache keys use tuples instead of per-frame concatenated strings. New and existing springs integrate real elapsed time rather than frame counts. Night mode retains velocities while targets change.

Isolated quality run: all 17 states settled; 1,291 repeated legacy transition frames had median 8.3333 ms and 95th percentile 8.3956 ms. Maximum measured island update-handler time in that run was 0.3053 ms. Some cold/first-open state samples reached approximately 16.7 ms. Notification regression’s 788 samples had median 8.3332 ms and p95 8.3412 ms. These measure WPF composition callback cadence and the island update handler, not a GPU-present trace or physical pixel latency; they do not establish zero dropped frames, exact 8.33 ms for every frame, or performance under all system loads.

Validation: 109 automated unit checks; all 22 legacy state checks settled; original cover-art roundtrip/clear checks passed; native Windows notification delivery/removal/disconnect passed after deployment; native audio endpoint enumeration and notification subscription passed; night toggle binding/persistence/off passed; natural eye blinking was captured across 150 frames. Reviewed notification and legacy screenshots/baselines were refreshed for the intentional theme change. The eye recording’s bright-eye pixel count ranged from 0 to 92, demonstrating an actual natural blink. Artifact audit: 254 ARM64/neutral PE files, no errors, optional WeatherClient remains the only external HTTP source.

Physical headphone plug/Bluetooth reconnection, touch hardware, precision trackpad behavior, sustained battery profiling, multi-monitor refresh combinations and GPU present-time tracing remain unverified. Taskbar customization stays disabled.
